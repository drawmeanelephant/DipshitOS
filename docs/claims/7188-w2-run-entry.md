W2 implementation notes (all verified by `zig test user/src/wasm.zig` 13/13):

- **`parseInto` split:** `parse` returned a 77 KiB `Module` by value — the 32 KiB guest task stack would smash. `parseInto(m, bytes)` takes an out-pointer so the run entry's frame stays small.
- **Loader argv reality:** the ELF path refuses argv (`exec.zig` lines 424-428, "card 3e" — DSK3/ELF images refuse args); only the DSK3 flat image carries argv in the writable data tail. Hence WASM.BIN is DSK3 segmented (bss zeroed at load, argv rides the data tail), and `exec WASM.BIN HELLO.WASM` → argv[0]="HELLO.WASM" arrives via `_start(argc, argv)`.
- **`exec` no-args rule:** the DSK3 argv block is read-only 8×32 B in the program's own text page (claim 4636, card 3e) — argv[0] is the module name, exactly one arg.
- **Store is mmap'd, not .bss:** the loader's 256 KiB staging budget counts bss, so a 2 MiB store cannot be `.bss`. The run entry mmaps the linear memory at runtime (M29 anonymous mmap, slot 63); `memory.grow` past 32 pages still traps. WASM.BIN totals ~194 KiB (text 20,480 / data 30,576 / bss 144,888) — inside budget with headroom.
- **Imports:** `env.write(fd, ptr, n)` → `sys_write` (console byte-exact via the existing seam); `env.exit(status)` → `sys_exit(status)`. Everything else keeps trapping `imported_unwired` (the W1b seam, now W3's job).
- **Fixture determinism:** clang embeds the *output basename* in the name custom section and (without `-g0`) the source path in DWARF sections. With `-g0` + a fixed output basename the 411-byte module is byte-identical across builds — the gate pins `edb6407b…` (verified by two identical-name builds + the pinned fixture committed at `user/src/wasm-corpus/hello-env.wasm`, sha-matched).
- **Real bugs W2's fixture caught** (the C module exercises paths the hand-built fixtures didn't): the code-section count must be **defined** funcs (imports excluded — `parseCode` also writes into `funcs[imported_funcs..]`); the data section has the same flags-0/no-index-byte quirk as elem (a table-index byte only exists for flags==2); the section-order `seen` array was `[11]` but the data section id 11 is legal → OOB; clang emits a trailing `unreachable` after a noreturn `exit` call — the host-capture path now traps `guest_exit` instead of falling through.
- **Transcript deviation (documented):** the card's Touches list mentioned `tests/transcript-console.txt` for a `wasm run` help line; the monitor command is deferred to a later card, so the transcript is untouched — the touch is documented here as not-taken.
