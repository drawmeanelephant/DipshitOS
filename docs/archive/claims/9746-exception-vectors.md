## Root cause found during verification (pre-exit VBAR write breaks VZ)

Installing VBAR_EL1 BEFORE ExitBootServices is catastrophic on VZ: with the kernel's vectors live while pre-exit firmware Boot Services are still active, ~7/8 boots hang inside the firmware calls (marker ladder stopped at `M2_ENTRY`/`M2_CMAP!`, inside the capture_map window). The measured control: same image with a no-op install = 8/8 boots, `msr vbar_el1`-only install = 0/8. Root cause: writing VBAR replaces the firmware's own exception vectors while firmware code (SetVariable/GetMemoryMap/AllocatePool) can still take exceptions — those would land in the kernel's table. Fix: `exceptions.init` + `install` run immediately after `mmu.install_identity_map()` (post-ExitBootServices, post-TLBI), when the kernel owns EL1. With the fix: 8/8 `zig build run` boots, and the live `fault` gate passes 2/2.
