## Notes

**Why this card:** N2 made raw Ethernet frames flow both ways but nothing
inside them is understood. ARP is the first protocol that makes a network
usable: a guest that resolves a peer's MAC from its IP (send requests,
parse replies) and answers requests for its own protocol address can talk
to real peers, and IPv4/ICMP (N4) presupposes it. Every pattern N3 needs
is proven: TX of a bounded frame (N1's `net_send`), RX of a broadcast
frame (N2's drain + MAC filter — ARP requests are broadcast, so they are
already admitted), and bounded BSS state (the N2 FIFO).

**Observe, don't assume (claim-time questions):** (a) does the device
pad or trim the 42-byte ARP frames (real Ethernet's 60-byte minimum)?
— the socketpair attachment is raw datagrams; the injected/answered
frames are exactly the bytes the gate asserts. (b) any new device
behavior on the ARP exchange — recorded `[observed]` with a saved VZ log
only, never assumed. (c) the net device's used-buffer IRQ line remains
unobserved (N2's record) — drain stays polled.
