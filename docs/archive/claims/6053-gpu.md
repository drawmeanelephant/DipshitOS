## Notes

G1 proves the transport + a writable framebuffer end to end with a
solid fill; text (G2), Road Pops (G3), input (G4), and Driving Award
(G5) are separate cards. Claim-time observations (recorded in
`docs/hardware-contract.md` with the saved VZ logs
`artifacts/m6-gpu-*`):

- **DID 0x1050 confirmed** (class 0x038000, bus 0 dev 7) — the modern
  virtio-pci gpu, found via the ECAM walk exactly like the
  console/blk/entropy/net devices. The device config layout is
  claim-0013's decoded shape: common cfg @ BAR0+0x0000, ISR @ +0x1000,
  notify @ +0x4000 (multiplier 4), device cfg @ +0x8000.
- **Feature negotiation:** the device offers
  RING_PACKED|RING_EVENT_IDX|RING_INDIRECT_DESC|VERSION_1
  (`devfeat=0x30000000/0x5` — the same word as the console) and accepts
  **VERSION_1 only** (`feat=0x0/0x1`) — split rings, classic 16-bit
  notify with the queue index as the value.
- **Reset at ExitBootServices: YES** — `gpu: pre-rearm st=00` observed
  (like blk/entropy, unlike net's `st=0f`); the post-exit re-arm is
  required and works.
- **Framebuffer exposure: the spec 2D command path** — GET_DISPLAY_INFO
  → RESOURCE_CREATE_2D → RESOURCE_ATTACH_BACKING (one mem_entry over
  the fixed BSS framebuffer) → SET_SCANOUT → TRANSFER_TO_HOST_2D →
  RESOURCE_FLUSH, all on the control queue with one command outstanding
  at a time. No resource mapping / BAR window (the alternative exposure
  was not needed).
- **Pixel format: B8G8R8X8_UNORM (format 2)** — the scanout resource;
  memory bytes B,G,R,X. The X byte must be **0xff (opaque)** — VZ
  composites with alpha, and an X/A of 0 renders fully transparent (the
  final black-screen bug).
- **virtio-gpu 1.2 wire shapes:** `display_one` is 24 bytes (rect +
  enabled + the 1.2-added flags); the GET_DISPLAY_INFO response is 408
  bytes. The pre-1.2 20-byte shape (344-byte response) wedged the
  device — DEVICE_NEEDS_RESET (0x40) on the first command.
- **VZ quirks observed:** the tail descriptor's `next` must be 0 (VZ
  walks the field even without the NEXT flag — 0xffff wedged the
  queue); the command buffer and the framebuffer caches must be
  cleaned (dc cvac) before the kick / transfer — an MMU-on kernel is
  not the caches-off world of the reference drivers; the cursor queue
  (queue 1) is armed for device compatibility (Linux configures both
  queues) and is never driven by G1 (input is G4).
- **Scanout:** GET_DISPLAY_INFO reports 1280×720 enabled — matching the
  runner's configured scanout.

No syscall numbering (ADR 0007 frozen), no heap, no
scheduler/process/lifecycle changes.
