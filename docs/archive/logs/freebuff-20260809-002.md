**Root cause found en route (the interesting bug):** `write` failed with `EFI_OUT_OF_RESOURCES` even on a fresh store. VZ's variable store is append-per-write, and the default build was writing ~62 KiB/boot of diagnostics into it: (1) the virtio TX flush persisted `M2_TXST!/TXNT!/TXPL!` on **every** flush — ~113 flushes/boot ≈ 30 KiB; (2) `write_probe_tail` also per flush; (3) `virtio_pci_init` still persisted the ~32 KiB probe dump in default builds (I'd gated only the `main.zig` call site). Store-free at boot 55,696 B → 24 B by shell time. Fix: per-flush markers + probe tail now write only on the **first** flush (preserves the hang-site evidence path every ladder-reading gate needs — preexit-tx/tx-transition/t0sz16 all analyze only the first flush), and the probe persist is gated behind `-Dprobe-var`. After the fix, a single boot leaves ~123 KiB free and `write` persists (store deltas: M2 354→20, P2 20→1, no P chunks).

**Results:** `verify-live-fs.sh` PASS 1/1 pair — run A persisted `hello world`, run B (same store, fresh boot) still lists `hello.txt [nvram]` and cats it.
