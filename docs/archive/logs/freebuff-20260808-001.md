- **2026-08-08** — *buffy*: coordination tooling hardened (claim 1801) — exact before/after behavior:
  - **Before — table-cell escaping:** `tools/status/refresh-indexes.sh` interpolated claim Owner/Status text and log titles into Markdown table rows raw; a literal `|` in that text split the row into extra columns, silently corrupting the shared index. No current claim triggers it (grep over `docs/claims/*.md` found no `|` in Owner/Status), but it was one unescaped character away. **After:** every generated cell passes through `esc()` (`\` → `\\`, `|` → `\|`), so a status containing `|` now renders as a valid 3-column row.
  - **Before — structural validation:** `--check` only diffed the tables against the generator's own output, so a broken generator passed because it was consistent with itself. **After:** `refresh-indexes.sh --check` runs a per-row structural check first (every row must have exactly 3 claim / 2 log columns, honoring `\|` escapes); a raw `|` in a row now fails with `error: CLAIMS_INDEX row N has M cells (expected 3)` before the sync diff runs. `verify-coordination.sh` inherits it via its `--check` call.
  - **Before — claim numbering:** sequential "next NNNN" collided under concurrency — claim 0013 was claimed by serial-discovery (10:27) and status-reverify (15:18) on 2026-08-07, and the loser was manually renumbered 0013→0014 (`be811cb`). **After:** `tools/status/claim-id.sh` derives the ID deterministically from branch+slug (`0024 + cksum("<branch>:<slug>") % 9976`, always in `[0024, 9999]`), so concurrent claimers pick different IDs without editing any shared file; `verify-coordination.sh` recomputes the ID for every claim numbered 0024+ and fails on mismatch (claims 0001–0023 grandfathered). This claim itself is the first derived ID: `1801`.
  - **Tests:** new `tools/status/test-coordination.sh` (15 cases, all passing) — positive: `|`/`\` in a claim status stays escaped and the index stays valid (`--check` + `verify-coordination` green); a claim numbered via `claim-id.sh` passes; `claim-id.sh` is deterministic/range-checked/rejects bad slugs. Negative: a raw `|` injected into a table row (as a broken generator would emit) fails `--check` and `verify-coordination`; a hand-sequenced `0024` claim fails the deterministic-ID gate. Wired into `just verify`, `just test-coordination`, and CI (`.github/workflows/ci.yml`).
