# Milestone 1.5 — commands & personality: design and self-review

Status: design complete and self-reviewed · Branch: `agent/buffy/m15-commands`
Date: 2026-08-06 · Prompt: `docs/m15-commands-prompt.md` (agent C)

This design is subordinate to AGENTS.md, `docs/status.md` (M1.5 steps
12–18, coordination rules), ADR 0002/0004, and `docs/m15-commands-prompt.md`.
It builds **against a mock console only**; no live serial RX is required and
no hardware claim is made. `kernel/src/main.zig` is not edited.

## 1. Goal and scope

A reusable, testable command layer for the future interactive Dipshit
Monitor (`dipshit>`), delivered as new kernel modules exercised by
host-side `zig test`. The layer is transport-agnostic (PL011/16550/virtio
or anything later) and state-free beyond an explicit, caller-owned context.

## 3. Console abstraction (`console.zig`)

`Console` is a value type holding `ctx: *anyopaque` plus a `VTable` of
function pointers (`write`, `flush`). Kernel wiring later supplies an
adapter over `uart_*`; tests supply `MockConsole`, which appends to a
fixed `[capacity]u8`, sets an `overflowed` flag when full, and counts
flushes. Convenience methods (`putc`, `puts`, `printHex`, `printHexMin`,
`printU64`, `printLine`) are pure functions over `write`.

Hex format is fixed for determinism: `0x` + lowercase digits;
`printHex` zero-pads u64 to 16 digits (matches the kernel's existing
`uart_hex`), `printHexMin` prints minimal digits (shell utility style).

## 4. Command registry and execution API (`monitor.zig`)

```zig
pub const Command = struct {
    name: []const u8,
    help: []const u8,      // one line, registry-derived help output
    usage: []const u8,     // printed on argument-count violations
    min_args: u8,
    max_args: u8,
    handler: *const fn (m: *Monitor, args: []const []const u8) ExecError,
};
pub const registry: [14]Command = ...;   // comptime, no dynamic registration
pub fn lookup(name: []const u8) ?*const Command;
pub fn exec(m: *Monitor, argv: []const []const u8) ExecError;
```

- `argv[0]` is the command name; the handler receives `argv[1..]`.
- `exec` does lookup, central arg-count validation (prints `usage: …` and
  returns `.usage`), then dispatches. Unknown names print
  `unknown command: <name>` + a hint and return `.unknown_command`.
- `help` output is generated by iterating the registry (name column +
  help text); it cannot drift from the registry.
- `ExecError` = `none | unknown_command | usage | invalid_argument |
  not_implemented`. Handlers print their own diagnostics; the enum is for
  programmatic/tests use.
- No allocation: fixed arrays, byte-at-a-time formatting, no join buffers
  (repetitions are streamed directly to the console).

## 5. System state and machine control

`Monitor` holds three caller-owned values:

```zig
pub const Monitor = struct { console: Console, state: SystemState, machine: MachineControl };
pub const SystemState = struct { handoff: HandoffV2, map: MapView, console_name: []const u8 };
```

`MachineControl` mirrors `Console`: `ctx` + vtable with `reboot` and
`shutdown` returning `MachineResult = ok | not_implemented | failed`.
`MachineControl.disabled()` returns the honest default (both
`not_implemented`). This is what lets tests exercise `reboot`/`shutdown`
fully without rebooting the test process. The real post-ExitBootServices
mechanism (`ResetSystem` via the captured Runtime Services table) is
**not proven** by any gate, so the kernel default is `disabled()` until a
later stream proves it (documented fallback: the terminal WFE loop
continues).

## 6. Commands (14, ≥ 10 required)

Formatting rules: numbers are lowercase hex with `0x`; u64 fields are
zero-padded to 16 digits, u32 to 8. No invented release number.

| Command | Behavior (deterministic) |
|---------|--------------------------|
| `help [cmd]` | Registry-derived listing; `help <cmd>` prints that command's help + usage |
| `about` | From-scratch AArch64 OS, freestanding Zig, no libc/POSIX, VZ host, ADR 0004 kernel proper, monitor tested against mock console (no live-claim) |
| `version` | Build info: kernel name, milestone, handoff ABI v2, build label (no release number — the repo defines none; "DIPSHITOS 0.1" exists only in the DoD screen sketch) |
| `uname` | `DipshitOS aarch64`; no POSIX claim |
| `handoff` | Prints validated handoff-v2 fields (magic, version, base, size, system table, image handle, stack bounds, flags) + `status: valid/invalid <reason>` |
| `mem` | From the captured map view: descriptor count/size/version/key, per-category bytes+pages (usable, conventional, loader, boot services, runtime, reserved, mmio) and kernel image bounds from handoff. Totals derived from the map — never hardcoded |
| `echo` | Args joined by single spaces + newline (no join buffer; streamed) |
| `clear` | `ESC[2J ESC[H` (documented ANSI sequence) |
| `hex <n>…` | Parses decimal or `0x`-prefixed hex (bounded u64, explicit invalid-input error), prints minimal `0x…` |
| `repeat <count> <text…>` | Repeats text on its own line per repetition; count 1..64, total output ≤ 4096 B, else explicit error (prevents infinite/runaway output) |
| `reboot` | Calls `machine.reboot()`; reports ok / not implemented / failed |
| `shutdown` | Calls `machine.shutdown()`; same reporting |
| `elephant` | Fixed mascot art + operational diagnostics (console transport, handoff validity, descriptor count) |
| `beans [count]` | Deterministic absurdity; optional count clamped-checked 1..100 |

Boot-message personality (step 18): a fixed message pool with a
deterministic, stateless selector keyed on a state field
(`image_handle`), plus a `banner()` helper the later shell stream prints.
The `dipshit>` prompt rendering itself belongs to the shell-core stream.

## 7. Safety constraints honored

- No heap allocation, libc, POSIX, dynamic registration, unbounded
  recursion, unbounded output, or hidden mutable globals (the only
  mutable state is caller-owned `MockConsole`/mock-machine structs).
- All arithmetic is fixed-size; parse and repeat enforce explicit bounds.
- `memmap.MapView` reads descriptors through a stride-aware accessor so a
  non-dense EFI descriptor stride cannot misalign reads.

## 8. Filesystem decision (step 15)

**Decision: defer fs commands (`ls`/`cat`/`write`/`touch`) to a storage
driver milestone.** Post-ExitBootServices there is no ESP root (x3
carries handoff v2) and no Simple File System; the pre-exit file window is
not built in this stream. Hard gate 5 ("fs commands persist through
reboot") stays open and is recorded as such in `docs/status.md`.

## 9. Tests (host-side, `zig test kernel/src/monitor.zig` etc.)

Registry lookup; help derived from registry; unknown command; arg-count
validation; version/uname/about output; handoff formatting + validation
rejections; mem summary arithmetic; echo; hex valid/invalid; repeat
bounds (0, 65, total-cap); reboot/shutdown via a mock machine control
(ok, not_implemented, failed) and via `disabled()`; elephant; beans;
output-buffer overflow behavior (small `MockConsole`, large output).
