# Log — agent/buffy/issue-613-tcp-connect-spin

- **2026-08-28** — *buffy (agent/buffy/issue-613-tcp-connect-spin)*: claim 2572 opened → issue #613 (`sys_tcp_connect` drain spin exhausts before VZ SYN-ACK delivery — spurious EINVAL with the handshake answered host-side). Investigated root cause: `handle_tcp_connect` in `kernel/src/syscall.zig` iterated at most 1,000,000 times polling `virtio_net.net_rx_drain()`. On Apple Silicon, 1M empty drain iterations take ~10–20 ms, racing host VZ delivery of the SYN-ACK frame and returning EINVAL while the host responder answers normally. Additionally, `tcp.now_ticks` was not advanced inside the syscall loop (timer IRQs are masked in EL1), so `tcp.connect_timed_out()` could never fire and `tcp.poll_rto()` was never serviced. 🔄 in progress.
- **2026-08-28** — *buffy (agent/buffy/issue-613-tcp-connect-spin)*: claim 2572 completed ✅. Made `timer.cntpct()` public with host-test guard. Replaced tight iteration loop in `handle_tcp_connect` (`kernel/src/syscall.zig`) with real wall-clock elapsed time tracking via `timer.cntpct()` / `timer.freq`, advances `tcp.now_ticks`, services `tcp.poll_rto()` for SYN retransmission, enforces 30s `tcp.connect_timed_out()`, inserts a 1,000 NOP spin delay to prevent memory bus contention, and cleans up connection state via `tcp.release_conn()` on error/closed state. Added unit tests in `kernel/src/syscall.zig`. All unit tests (`verify-unit-tests.sh`) and live VZ gates (`verify-live-net-tcp-syscall.sh`, `verify-live-fetch.sh`, `verify-live-net-tcp.sh`, `verify-live-net-tcp-rto.sh`, `verify-coordination.sh`) pass 100%.
