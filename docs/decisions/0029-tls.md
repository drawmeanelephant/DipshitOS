# ADR 0029: TLS 1.3 client and trust store

- Status: ACCEPTED
- Date: 2026-09-14
- Issue: #1262, #1264, #1265, #1266, #1267, #1268 (the TLS13 card series)
- Related: ADR 0023 (crypto primitives — this ADR extends its shelf and
  inherits its stated side-channel limit), ADR 0024 (trust and isolation),
  ADR 0013 D3.1 (.bss budget), ADR 0025 (SSH — the structural precedent for a
  protocol client in this tree), M40 GF6 (gate rules)

## Context

The goal was a TLS 1.3 client good enough to unlock HTTPS fetching and
git-over-https. The brief assumed the remaining work was "X.509 parsing, chain
validation, the handshake state machine" on top of an already-stocked crypto
shelf. Reading the shelf showed the assumption was one layer short: HKDF is the
entire TLS 1.3 key schedule (RFC 8446 §7.1), SHA-384 is needed for the SHA-384
suites, and `TLS_AES_128_GCM_SHA256` is mandatory to implement (§9.1) — so a
ChaCha-only client cannot reach much of the public web. None of the three
existed.

The temptation is to vendor a TLS library. That would import an unbounded
dependency into a freestanding OS whose userland has no allocator-heavy
services, and it would put the most security-critical code in the tree outside
the tree's own review and gate discipline.

## Decision

**D1. In-tree only.** No third-party TLS or X.509 library is linked. The
primitives the shelf lacked are implemented in-tree and pinned to published
vectors: HKDF (RFC 5869), SHA-384 and HMAC-SHA384 (FIPS 180-4), AES-128/256
(FIPS 197) and AES-GCM (NIST SP 800-38D), Montgomery bigint arithmetic with
RSASSA-PKCS1-v1_5/PSS (RFC 8017) and ECDSA P-256/P-384 (FIPS 186-4).

**D2. Every pinned value comes from an independent source.** RFC 5869 and
RFC 8448 are fetched and extracted with per-block octet-count validation; AES
blocks are generated with Go and cross-checked against OpenSSL and FIPS 197;
GCM is asserted against NIST GCM test cases 1 and 2; certificate fixtures are
generated with OpenSSL and every expected field is read back out of
`openssl x509 -text`. Nothing is transcribed from memory. This discipline caught
ten defects during construction, including three that would have produced
verifiers that pass nobody's signatures.

**D3. The handshake is a named state machine** (`handshake.zig:State`), not
implicit control flow. Application data is reachable only from `connected`, and
`connected` is reachable only after the server's `Finished` verifies. Expected
message ordering is data; an unexpected message is an error.

**D4. Fail closed, everywhere.** Every failure path returns a specific error or
`validate.Result` code; there is no partial acceptance. Three concrete rules
follow from this and are worth stating because each was a live bug first:
a self-issued certificate may not serve as its own trust anchor (the path walk
must terminate at an anchor in the store); a parsed certificate is a *view*, so
anything that outlives the buffer it came from is copied; and an unknown
**critical** extension fails the chain rather than being ignored.

**D5. The trust store is capacity-parameterised, caller-owned, and versioned.**
`trust_store.Store(N)` holds `N` anchors; the guest is expected to instantiate a
small vendored set (the default is 64, ≈160 KiB of .bss) while host tooling can
hold a full system bundle. Anchors are injected through `addRoot`, removable
through `removeRoot`, and the active set reports a version string at runtime for
troubleshooting.

**D6. Scope is the mandatory suite.** `TLS_AES_128_GCM_SHA256` with x25519.
No PSK, no 0-RTT, no client certificates, no HelloRetryRequest (rejected
explicitly rather than mishandled), no AIA fetching, no OCSP/CRL.

**D7. The consumers are wired, not re-architected.** The client is transport
agnostic: a consumer supplies a read/write vtable over its own TCP seam and a
trust store, and gets a `Client`. `INTEGRATION.md` in `user/src/lib/tls/`
carries the contract.

**D8. Rollback is a build-level pin.** The TLS roots are ordinary
`unit_test_sources` entries and the library is not yet linked into any guest
binary, so disabling it is removing those entries; see `CHANGELOG.md` for the
exercised procedure and its recorded result.

## Consequences

The client completes a real TLS 1.3 handshake against four independent peer
implementations and eight public endpoints, and fails closed against five
hostile or broken ones; the interop matrix and its ledger live in
`user/src/lib/tls/interop/`. The cost is that the tree now owns roughly 4,000
lines of security-critical code, so the vector discipline in D2 is load-bearing
rather than decorative.

Two limits are inherited rather than solved: AES is table-based, so S-box
lookups are not cache-timing constant-time (the same class of limit ADR 0023 D3
already declares), and verification paths are not constant-time because they
operate on public data.

## Not decided here

Revocation (OCSP/CRL) needs a live-network policy and is deliberately left to a
separate card. A guest gate for the live handshake needs a guest-side
`TLS.BIN` and a runner-side TLS responder; the gate design is fixed in
`INTEGRATION.md` and lands with that consumer rather than as a spec that cannot
run.
